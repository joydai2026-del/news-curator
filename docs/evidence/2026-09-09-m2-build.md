# News Curator M2 build record

Date: September 9, 2026 (America/New_York).

## Scope and current state

M2 is implemented on the prepared `feat/m2-discovery-lanes` branch, based on `4741a64744c35f98d9f14c1180470f9ccb766f95`. The approved reading-companion scope places M2 in the private signed-in hub. M1 learning remains separate and open. M3 through M5 are outside this change.

The sole Python engine generates Updates, Hot, Interested and Surprise, resolves overlap by the approved priority, applies source/topic/history constraints, preserves secondary reasons and checks the seven edition bands. The protected materializer fetches the actual configured owner's profile and database history itself. Only a replay-verified PASS can become a stored private edition. Browser and agent CLI read the same owner-only edition RPC. Public publication entries never receive personal lane assignments.

Normal edition policy is configurable in `config/discovery-policy-r2.yaml`; frozen r1 is unchanged. Storage, staleness and retained-history policy is configurable in the database within the common client safety envelope. The workflow feature flag remains off by default. This branch has not been deployed, and no real account or production database was changed during the build.

## September 10 follow-up: passing real-source edition

The initial FAIL exposed two implementation defects. Cold-start affinity counted the source-native Trending category as a subject interest, excluding eligible out-of-topic stories from Surprise. The selector also applied fixed item-count caps before checking the smaller final edition, leaving source concentration above the required percentage. Policy now explicitly excludes `trending` from cold-start subject affinity while preserving its topic chip, and selection applies final source/topic share caps with deterministic same-lane backfill and explicit shortages. Same-lane replacements also repair attainable minimum source/topic variety.

A fresh public capture at 2026-09-10 02:31:33.824945 UTC contains 3,811 source records. Replaying it against the genuine 01:18:50.021985 UTC capture through the agent CLI, with an explicitly declared first local edition, produces **PASS with all seven bands active and unchanged**:

## Remaining acceptance gate

The intended end state is an owner opening a settled, private, balanced four-lane edition with working read/save/history behavior. The implementation and controlled runtime tests establish the build path. Acceptance still requires a genuine owner-bound PASS edition, controlled release of the migration and feature flag, and live owner verification. The latest real-source local edition passes every unchanged band. A genuine owner-bound settlement and release acceptance remain separate from that engine proof; M2 remains unaccepted until those release checks are complete.

This work directly serves the approved M2 reader need. The implementation reuses existing collectors, auth, scheduled Python, Supabase and reader cards; no new hosted service or later-milestone scaffolding was added.
